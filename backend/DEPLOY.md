# 🚀 Як викласти сервер в інтернет

Покрокова інструкція. Робиться один раз, далі оновлення їдуть самі.

---

## Що ми взагалі робимо

Зараз сервер живе на твоєму ноуті за адресою `http://localhost:8081`.
Слово `localhost` означає буквально «цей самий комп'ютер» — з іншого пристрою
туди не достукатись у принципі. Поки так, гра на GitHub Pages бекенду не бачить.

Треба рознести гру на **три окремі місця**, кожне безкоштовне:

```
┌──────────────────────┐   гравець відкриває
│  GitHub Pages        │   mitsu-oi.github.io
│  сама гра (html/js)  │   ← вже працює
└──────────┬───────────┘
           │  «збережи мені гру», «дай картку»
           ▼
┌──────────────────────┐
│  Render              │   <ім'я>.onrender.com
│  Spring Boot сервер  │   ← робимо зараз
└──────────┬───────────┘
           │  «поклади це в базу»
           ▼
┌──────────────────────┐
│  Neon                │
│  PostgreSQL          │   ← і це теж
└──────────────────────┘
```

**Чому база окремо від сервера.** У Render є своя безкоштовна база, але вона
**самознищується через 30 днів** після створення. Neon дає безкоштовний план
**назавжди**, без прив'язки картки. Тому база — там.

---

## Крок 1. База даних на Neon

1. Зайди на **neon.com** → Sign up (можна через GitHub).
2. Створи проєкт:
   - назва — `studlife`
   - **регіон — Europe (Frankfurt)**. Це найближче до України: чим далі
     база, тим довше йде кожен запит. Той самий регіон потім обери на Render
3. Після створення покажуть **connection string** — рядок, у якому зашито
   все потрібне, щоб під'єднатись. Виглядає так:

```
postgresql://studlife_owner:AbCdEf123@ep-cool-name-12345678.eu-central-1.aws.neon.tech/studlife?sslmode=require
```

### ⚠️ Дуже важливо: бери connection string БЕЗ слова `-pooler`

Neon пропонує два варіанти: звичайний і **pooled** (з `-pooler` в адресі).
Pooled — це посередник, який економить з'єднання, розкладаючи запити по
спільних каналах.

Нам він **не підходить**. Наш Flyway (той, що створює таблиці) на час роботи
ставить на базу «замок», щоб дві копії сервера не почали створювати таблиці
одночасно. Замок тримається на конкретному з'єднанні — а посередник з'єднання
постійно підміняє. Замок губиться, і Flyway падає з незрозумілою помилкою.

Якщо в адресі є `-pooler` — перемкни в інтерфейсі Neon на прямий варіант.

### Розбираємо рядок на три частини

Java не розуміє цей формат — їй треба `jdbc:` на початку і логін із паролем
окремо. З прикладу вище виходить:

| Змінна | Значення з прикладу |
|---|---|
| `DB_URL` | `jdbc:postgresql://ep-cool-name-12345678.eu-central-1.aws.neon.tech/studlife?sslmode=require` |
| `DB_USER` | `studlife_owner` |
| `DB_PASSWORD` | `AbCdEf123` |

Правило: береш вихідний рядок, викидаєш `логін:пароль@`, спереду дописуєш
`jdbc:`. Хвіст `?sslmode=require` **лишаєш обов'язково** — це вимога Neon
шифрувати з'єднання, без нього не пустить.

> 🔒 Ці три значення — ключі від бази. Нікуди не викладай, у git не клади.
> Вони житимуть тільки в налаштуваннях Render.

## Крок 2. Сервер на Render

1. **render.com** → Sign up через GitHub.
2. **New +** → **Web Service** → під'єднай репозиторій із грою.
3. Налаштування:

| Поле | Значення | Чому саме так |
|---|---|---|
| Name | `studlife-backend` | стане частиною адреси: `studlife-backend.onrender.com` |
| Region | **Frankfurt** | той самий, що й у Neon |
| Root Directory | `backend` | ⚠️ у репозиторії лежить і гра, і сервер. Без цього Render шукатиме Dockerfile у корені й не знайде |
| Runtime | **Docker** | Render не вміє Java сам — тому ми й написали `Dockerfile` |
| Instance Type | **Free** | |
| Health Check Path | `/api/health` | адреса, за якою Render перевіряє, що програма піднялась |

Гілку лишай `main` — тоді кожен `git push` автоматично перезбиратиме сервер.

## Крок 3. Змінні оточення

**Environment** → **Add Environment Variable**. Вписати треба вісім штук:

| Змінна | Значення | Навіщо |
|---|---|---|
| `DB_URL` | твій jdbc-рядок із Кроку 1 | де база |
| `DB_USER` | логін із Кроку 1 | |
| `DB_PASSWORD` | пароль із Кроку 1 | |
| `GEMINI_API_KEY` | твій ключ Gemini | ⚠️ **тільки сюди**, ніколи у файли |
| `ALLOWED_ORIGINS` | `https://mitsu-oi.github.io` | кому дозволено звертатись |
| `COOKIE_SAMESITE` | `None` | див. пояснення нижче |
| `COOKIE_SECURE` | `true` | |
| `SHOW_SQL` | `false` | не засмічувати логи й не світити дані гравців |

`PORT` вписувати **не треба** — Render підставляє її сам.

### Чому COOKIE_SAMESITE=None — і чому це не діра

Після входу сервер видає браузеру cookie — «номерок гардероба». Браузер сам
чіпляє його до кожного запиту.

Але гра на `github.io`, а сервер на `onrender.com`. Для браузера це **різні
сайти**, і за замовчуванням він cookie між сайтами не передає. Це захист:
інакше будь-який сайт міг би тихцем слати запити від твого імені.

`None` вимикає це обмеження. Само по собі — так, ризиковано. Тому в нас три
запобіжники:

1. **CORS** (`ALLOWED_ORIGINS`) — сервер відповідає лише твоїй грі, не будь-кому
2. **`Secure`** — cookie ходить тільки по https, підслухати не вийде
3. **`HttpOnly`** — JavaScript цю cookie не бачить, украсти скриптом нема як

> Локально нічого міняти не треба: вдома діють значення за замовчуванням
> (`Lax` + без `Secure`), бо `localhost` працює по http, а `Secure`-cookie
> по http браузер просто викидає.

## Крок 4. Перевірка

Перша збірка йде **5–10 хвилин** (Docker качає Java і бібліотеки). Далі швидше.

Дивись **Logs** у Render. Що має бути:

```
Flyway ... Successfully applied 2 migrations     ← таблиці створились у Neon
Tomcat started on port 10000
Started StudlifeBackendApplication in ... seconds
```

Тоді відкрий у браузері (можна з телефона):

```
https://studlife-backend.onrender.com/api/health
```

Очікувано: `{"status":"ok","time":"..."}`

Якщо бачиш це — **сервер в інтернеті, Етап 17.5 закрито.**

## Що піде не так (найчастіші три)

**`FATAL: password authentication failed`**
Пароль скопійовано з обрізаним символом або ти взяла рядок від іншого проєкту
Neon. Перегенеруй пароль у Neon і перевстав усі три змінні.

**Збірка падає на `./gradlew: not found` або `Permission denied`**
Root Directory не `backend`. Render дивиться не в ту папку.

**Логи обриваються на `Killed` або сервер мовчки перезапускається**
Не вистачило пам'яті (512 МБ). У `Dockerfile` уже стоїть
`-XX:MaxRAMPercentage=70` — якщо все одно вбиває, опусти до `60`.

## Що треба знати про безкоштовний тариф

**Сервер засинає після 15 хвилин без запитів.** Наступний гравець чекатиме
**близько хвилини**, поки той прокинеться. Це не поламка — так влаштований
безкоштовний план.

Що з цим робити:
- в Етапі 18 гра смикне `/api/health` ще на екрані входу — поки гравець
  вписує пароль, сервер уже встане
- офлайн-fallback на `localStorage` лишається обов'язковим

**⚠️ Після сну всі виходять із акаунтів.** Зараз сесії живуть у пам'яті
програми — сервер заснув, пам'ять очистилась, номерки недійсні. Гравцеві
доведеться логінитись щоразу.

Лікується перенесенням сесій у базу (Spring Session JDBC). Робимо це **після**
того, як переїзд запрацює — щоб не ловити дві незрозумілості одночасно.

**750 годин на місяць на весь акаунт.** Один сервіс, який спить уночі,
в ліміт вкладається спокійно.

## Оновлення надалі

Просто `git push` у `main`. Render сам помітить, перезбере й перезапустить.
Заходити в інтерфейс треба лише щоб змінити змінну оточення.
